Import a PlotEdge project

Restore a .plotedge.json backup exported from this or another device — features, photos, notes, sketches and the feature-type schema all come back intact. Imports are always additive: the file lands as a new project and nothing already on this device is overwritten.

Import data

Bring in a .gpkg or .csv file captured in QGIS, ArcGIS, or another field app.

GeoPackage import loads the same small SQLite engine used for GeoPackage export (needs network signal once, then works offline). CRS is auto-detected: WGS84, UTM zones, and Web Mercator reproject automatically; anything else is flagged and skipped per-layer rather than imported in the wrong place.

Web map (GitHub Pages)

Publishes a live, view-only map of this project's features to a free GitHub Pages site — shareable with anyone by link, responsive on phone or desktop. PlotEdge talks to GitHub directly from this browser; there's no PlotEdge server involved.

  1. Create one empty GitHub repo to hold all your published maps (only needs doing once) — create it on GitHub.
  2. Create a fine-grained personal access token, scoped to just that repo, with Contents: Read and write and Pages: Read and write permissions.
  3. Paste the token and repo name below.
The token is stored only in this browser (localStorage) and used only for direct calls to api.github.com — never sent to PlotEdge or anywhere else. Use "Disconnect" any time to remove it from this device; it doesn't touch anything already published.
The published page is view-only — visitors can't edit your data. To change what's shown, edit the project here in PlotEdge and tap "Update web map" again.
PostGIS (push to a database)

PlotEdge runs fully offline with no server, so it can't write to a database directly from the browser. Fill in your connection details and get a ready-to-run command to load your latest GeoJSON export into PostGIS.

This generates an ogr2ogr command you run on your own machine after exporting GeoJSON above. Your database password is never entered here or sent anywhere by PlotEdge. A live "push" from the browser would need a backend proxy holding the connection string server-side, which is a separate, optional project since it makes the app network-dependent.
Photo backup

Photos always stay in this browser first. Turn on either option below to also back them up as they're captured, instead of only at export time.

Writes into <folder>/<Project name>/exports/, overwriting the same file each time (_latest) rather than piling up a new export on every single capture. The folder always holds one current snapshot, and the manual Export section below is still there whenever you want a timestamped copy instead.
Cloud backup needs a small serverless function you deploy yourself (Netlify Function or Cloudflare Worker). PlotEdge only calls the URL you paste in; no database credentials live in this app. Device-folder saving uses the File System Access API (Chrome/Android/desktop) and falls back to the one-at-a-time download used by "Download Photos" on browsers without it, like Safari/iOS. Uploads queue locally and retry automatically once you're back online.
AI photo recognition

Same no-server-required approach as photo backup above: paste an endpoint that takes a photo and returns a short label (e.g. "utility pole", "cracked pavement"), and PlotEdge tags each new photo automatically. This one needs network access when it runs, so it's the one part of PlotEdge that isn't fully offline.

PlotEdge posts { image: dataUrl } to your endpoint and expects { label: "..." } back — your function is free to call whichever vision API/model you choose server-side; no keys are ever stored in this app. A photo is never blocked or lost if recognition fails or is unset — it just won't have a label.

Help & about
What PlotEdge is
An offline-first field GIS. Everything you capture is written to this device and stays there until you export it — there is no account, no server, and no background sync.
The two ways to make a feature
Capture walks the geometry with GPS, recording accuracy and a timestamp at every vertex. PlotEtch draws it by tapping a map, for anything you can see but can't walk. A PlotEtch sketch has no accuracy figures, so it isn't a real feature until you send it to Capture and save it there. PlotAtlas is the full-screen map for reviewing everything captured, and PlotLens turns a set of photos into a narrated story.
Feature types come first
A feature type is your schema: the geometry kind plus the attribute fields collected against it. Capture and Save stay disabled until at least one exists.
Working offline
Capture, edit, review and export all work with no signal. Map tiles are the exception — they need a connection at least once, after which recently viewed tiles are cached. GeoPackage import/export fetches a small SQLite engine on first use, so run one export while you still have signal if you'll need it in the field.
Your data lives in this browser
Features are stored in localStorage for this site. Clearing site data, uninstalling the app, or "clear browsing data" will erase them. Use "Backup all projects (.json)" on the Projects screen regularly — it's the only copy, and it's the one format "Import backup" can read back in to restore everything (features, photos, notes, sketches) on this or another device. The GeoJSON/CSV/GeoPackage exports are one-way, for other GIS software.
Measurement
Lengths and areas use haversine geodesics on WGS84, not planar approximations. PlotEtch's buffer, intersect and clip are grid-sampled approximations — good for planning, not for cadastral work.
PlotVault

Point PlotEdge at a FlatGeobuf (.fgb) file on your bucket. Only the features inside the map view you are looking at are transferred — a large dataset stays on the server.
